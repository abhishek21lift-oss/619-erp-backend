## How it works today

- **Provider:** OpenRouter only (`provider_settings.mode = openrouter`, no Gemini).
- **Built-in defaults:** free-tier models (`openai/gpt-oss-120b:free`, `poolside/laguna-m.1:free`, `nvidia/nemotron…:free`).
- **What production actually sends:** `"auto"` (151 of 176 calls in the last 30 days). There are no database overrides, so this comes from the server's environment settings. `"auto"` is an auto-router that picks a different underlying model per request.
- **Last 30 days:** 176 calls, 180,764 tokens, and 11 fallbacks to a backup model.
- **Stored:** 72 conversations and 234 messages (oldest 23 Jul), 46 workout generations, 8 knowledge-base documents.
- **Quota enforcement:** off (`ai_platform_settings.enforcement_enabled = false`, no monthly cap).

## What is done well

These were checked and hold:

- **AI tools are read-only and tenant-scoped.** Every query in `tools.js` filters on the caller's organization. Each tool declares its roles, and a tool that names no roles fails closed.
- **The model is never in the write path.** `ai-actions` is propose → plan (stored with a fingerprint and a 5-minute expiry) → explicit confirm. The server re-resolves the plan and refuses if anything moved. At most a capped number of recipients can be reached.
- **RAG is tenant-scoped at document level:** `is_global OR organization_id = caller`. A studio can't create global documents, and every knowledge route requires a trainer.
- **Conversations are owner-checked** (`id AND user_id`). A foreign `client_id` is dropped rather than persisted.
- **Prompt-injection framing:** trainer-typed text, RAG chunks and the exercise library are marked "data, not instructions". Because tools are read-only and actions need confirmation, a successful injection can't write or send anything.
- **The workout generator refuses** a client whose PAR-Q gate is explicitly not cleared (`409 NOT_CLEARED`). It warns loudly for unscreened clients, and asks new-vs-adapt when a programme is active.
- **Chat output is rendered through `ChatMarkdown`** (react-markdown, no raw HTML). Links open with `noopener`. The generators say "review before saving".
- **There is a fallback chain** across model tiers, and the model that actually answered is recorded for streams.

## Findings

### AI-1 (High, privacy): client health and personal data go to third-party models with no data-collection opt-out
Prompts carry client **names, mobile numbers and outstanding balances** (the `find_client` and dues tools). They also carry **health conditions, injuries, medical conditions, allergies and PAR-Q-derived limitations** (the workout and diet generators and chat context).

The problem:
- `openrouter.js` sends none of OpenRouter's privacy controls: no `provider.data_collection: "deny"`, no zero-data-retention routing.
- The defaults are free-tier endpoints, and `"auto"` can route anywhere. Free endpoints are generally ones whose providers may log prompts.
- **No consent text** (enrolment, PAR-Q consent, informed consent) mentions AI or third-party processing.

Under India's DPDP Act 2023, health data needs a stated purpose and consent. This is the most important AI finding.

**Fix:**
1. Send `provider: { data_collection: "deny" }` (and prefer ZDR endpoints) on every request.
2. Stop sending mobile numbers and exact balances to the model. Tools can answer those without the model seeing raw contact details.
3. Pin paid models from providers that don't train on prompts, instead of `:free` or `auto`.
4. Add an "AI-assisted coaching" clause to the consent the client signs.

### AI-2 (High, safety): the AI's medical gate disagrees with the real screening gate
`client-context.js` builds the AI's picture of the client from **its own read** of `pt_parq_forms`. It takes the latest row, **drafts included**, and trusts the **stored** `workout_gate_status`:
- **No clearance expiry:** a clearance that expired still reads "cleared".
- **Drafts count:** a newer blank **draft** PAR-Q (gate "cleared") hides a submitted high-risk one.
- **Consent ignored:** revoked consent and "physician advised against" are not considered.

The assignment and session gate (`lib/screeningGate.js`) was fixed for all of these on 28 Sep. The AI path wasn't, so the generator can write a programme for a client the rest of the app would refuse to train.

**Fix:** derive `rules.gate` from `screeningGate.evaluate()` so both paths use one rule.

### AI-3 (Medium-High, cost and abuse): no effective AI limit, and no visibility of spend
- **No cap:** quota enforcement is off and has no default cap. The only limit is the generic 200 requests/min per user, which isn't a meaningful limit for LLM calls.
- **Paid routing:** `"auto"` can route to paid models.
- **No spend or speed data:** `ai_usage_log` records **₹0 cost and 0 ms latency on every one of the 176 calls**, so there's no way to see spend or slowness.
- **Fails open:** the quota check lets a request through when the check itself errors.

**Fix:**
- Set a default monthly token cap and turn enforcement on (the Command Center has the switch).
- Add an AI-specific per-user limit (for example 10/min for generations, 30/min for chat).
- Record the real latency and the provider's cost (OpenRouter returns usage and cost).

### AI-4 (Medium, quality): `"auto"` makes output inconsistent and unexplainable
The same generator can answer with a different model each time, so plan quality and safety behaviour vary between requests. It was noted earlier that `ai_workout_generations` recorded "auto" in the column meant to say which model wrote a plan. Streams now record the served model, but `ai_usage_log` still shows `auto`.

**Fix:** pin a primary model per tier, and log the served model in usage.

### AI-5 (Medium, retention): AI conversations are kept forever
The 234 stored messages include client names and health context. There is no retention period and no automatic deletion. They survive a client being deleted.

**Fix:** a retention window (for example 180 days) and deletion alongside the client.

### AI-6 (Low): intent routing includes developer intents
`models.js` routes `code`, `sql`, `debug` and `refactor` to a coding model, and business and finance questions to the "fallback" tier. A studio app has no use for developer intents. Finance questions going to the least-capable tier also means money answers get the weakest model.

### AI-7 (Low): no "AI-generated, not medical advice" note in AI Coach chat
The generators say "review before saving", but the chat, which answers training and nutrition questions directly, has no such note.
